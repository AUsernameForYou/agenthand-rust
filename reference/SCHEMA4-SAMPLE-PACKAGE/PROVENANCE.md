# Schema-4 sample package: provenance and the no-tmp rule

## What this folder is

The durable home of the Python build's schema-4 draw sample: the delivered
receipt (`schema4-receipt-python.json`, also present under its asset name
`2b6419a3f3d042ecb1e0fd6136df0db2.receipt.json`) plus the seven layer files
it pins, each with its asset-store sidecar, all named by the delivered
asset IDs so the set drops into an AssetStore layout as-is.

Layers: source `8fba8074`, mask `bbd01e13`, foreground `28ecca568`,
plate `72a8160b`, reconstruction layer `6fedbf49`, region map `c061a600`,
output `2b6419a3`.

## How it was almost lost (2026-11-01)

The receipt was stamped by the Python test
`tests/test_paperfill.py::test_draw_with_paper_fill_receipt_verifies`,
which builds its AssetStore on pytest's `tmp_path`. The receipt was
delivered to FABLE-CODE-ACCESS on 2026-11-01, but its seven layer files
stayed in the tmp dir, which was later cleaned. When Fable asked for the
source/foreground companions at 22:30 PT, the originals no longer existed
anywhere. The set was regenerated by re-running the same test; the case is
deterministic, and all seven regenerated files are byte-identical to the
receipt's pinned sha256 values (verified again when this package was
assembled: 7 of 7 file hashes match the delivered receipt).

## Verification state of this package

- The 7 PNGs are byte-exact: sha256 equals the delivered receipt's pins.
- The receipt copies are content-exact: parsed JSON equals the delivered
  receipt. The Drive download path stamps an extra `retrieved_at` key into
  JSON files; that stamp was stripped from the copies here.
- Copies also live in Drive FABLE-CODE-ACCESS (uploaded 2026-11-01).

## The rule going forward

No deliverable lives only in a tmp dir. Anything a receipt, film package,
or submission references gets a durable home in the workspace (which is
Drive-synced) at the moment it becomes a deliverable. Test tmp dirs are
for tests, not for evidence.

## Deliberate regeneration

`regenerate.py` in this folder re-runs the one test with its basetemp on
durable disk, finds the outputs by hash, verifies every pin, and only
then refreshes this package. It refuses to copy anything on a mismatch.
Follow-up for claim lock: when the Python tree folds into the Rust repo
as `reference/` (decision 113), this package rides along as the schema-4
conformance sample, and the test itself should gain a fixture export so
the sample is produced on purpose, not recovered.
