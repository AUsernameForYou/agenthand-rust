# agenthand — Rust port (PARALLEL EXPERIMENT)

Status as of 2026-10-28. This repo is an experiment next to the
shipped Python product in `~/workspace/agenthand`, which is
untouched and remains the product. The port earns "parity" only
through the gate below; this file says exactly where it stands.

**Completion lane (2026-10-28): the remaining Python-only pieces
are ported.** PNG eXIf orientation on ingest (4192357), receipt
persistence beside the composite with the hardened verify loading
(25fec5c), and the scale-card estimator (25794b0). The parity gate
was re-run after all three landed: still PASS, same hashes. What
remains unported is listed bluntly at the bottom (HEIC is the one
deliberate exception).

## Verdict

**Parity gate: PASS.** The Rust fidelity core, fed the frozen
verified run's layer/mask/plate, reproduces the frozen receipt
exactly: changed_opaque_pixels = 0 over 580,613 checked opaque
pixels, and the recomposed output's pixel hash is byte-identical
to the frozen composite's. The MCP server runs over stdio with the
same three tool shapes.

**Live path: PROVEN for identify, cut_out, and draw
(2026-10-27, see "Live run" below).** One live chain ran from the
Rust binary over stdio against the Meta API. Draw initially failed
because muse-image-1.0 returns a **WebP** payload by default and
the Rust image decoder speaks PNG/JPEG only. A one-call probe then
confirmed the images endpoint honors `output_format: "png"`; the
Rust plate request now sends that parameter, and the follow-on
live draw succeeded. Python's standalone verifier independently
checked the exported Rust source/final/mask and passed it.
Two transport bugs had to be fixed first (proxy/TLS, below). The
gate and the test suite remain offline.

`live-run-2026-10-27.json`.

  now sends that parameter. Reusing the stored cut_out foreground,
  one live draw then settled **$0.01** (18,134 in / 1,730 out
  usage tokens) and produced plate `asset://ce5faa2254554682b0007a480359be9f`

- **Rust live receipt:** 229,953 opaque pixels checked,

  (no embedded profile on either side), output pixel sha256

- **Cross-implementation check — PASS.** The source, final, and
  mask were exported to `live-data/exports/{source,final,mask}.png`.
  Python's `agenthand.verify` reported `ok: true`, 229,953 checked
  pixels, 0 changed, 0 edge-band pixels, and colour profile
  preserved, with no problems.
- **Ledger and total cost:** the successful chain settled
  **$0.030204** (standalone identify 0.009377 + internal plan
  identify 0.008327 + SAM cut_out 0.0025 + draw 0.01). The
  live-data ledger's counted total is **$0.040204** because the
  earlier failed draw's $0.01 reservation stayed counted
  (fail-closed, as designed). Adding the separate $0.01 format
  probe makes **$0.050204** of API spend associated with the live
  experiment — far under the $120 working cap / $150 hard ceiling;
  the reserve-before-call gate held on every Rust-server call.
  Two earlier aborted driver runs died at TLS connect (below)
  before any request reached Meta: their ledgers counted a
  $0.024798 reservation each, but no API spend occurred.
- **Transport fix (the reason the first live attempts failed):**
  this VM's env names a TLS-intercepting egress proxy; reqwest
  auto-detects it, and the proxy presents certificates signed by
  a local CA that rustls (webpki roots) rejects —
  `InvalidCertificate(UnknownIssuer)` on every call. Python never
  hit this (httpx validates against the OS store, which trusts
  the local CA). Direct egress presents the genuine DigiCert
  chain, so `meta::build_client` now builds with `.no_proxy()`.
  Trade-off, stated plainly: on a network where a proxy is the
  ONLY egress, this client cannot connect until it also trusts
  that proxy's CA.

## Design choices

- **Hand-rolled JSON-RPC stdio loop, not rmcp.** Deliberate: exact
  wire-shape parity with the Python server (dict results as a text
  content block plus structuredContent; draw's preview as an image
  block; `asset://{asset_id}` resource template) and no SDK
  version skew. The transport is ~150 lines and fully covered by
  the e2e test.
- **Pillow semantics ported from C source** (Resample.c,
  AlphaComposite.c, Convert.c at the 13.0.0 tag): fixed-point
  bicubic coefficients, the 8-bit two-pass resample, premultiplied
  RGBa resize for RGBA inputs, and Pillow's exact
  alpha_composite rounding.
- **SAM codec ported from meta-sam-parser 0.1.0**: base85 with the
  SAM alphabet, the arithmetic range coder, and both payload
  codecs (one_bit context model, lossless predictor model),
  including the canonical re-encode check on one_bit decode.
- **Billing**: reserve/settle JSONL ledger under an exclusive file
  lock, pricing table version `2026-10-26.2` (same as Python),
  $120 default cap under the $150 hard ceiling, unknown models
  refused. Key from `META_API_KEY` (env, or `.env` in cwd / exe
  dir / crate dir — env wins); the value is never printed.
- Subcommands: `serve` (default; the MCP server), `parity <dir>`,
  `verify <source> <final> <mask>` (exit 0/1, port of
  agenthand-verify), `measure <image> <card> [--profile <path>]
  [--bbox x,y,w,h]` (the estimator; JSON result on stdout,
  `{"error": ...}` on stderr with exit 1, as Python's CLI).

## What is stubbed or missing (blunt)

- **Default WebP plate payloads remain unsupported locally.**
  The live draw path avoids them by requesting PNG from the API;
  if a future response ignores `output_format`, the hand-rolled
  decoder still rejects WebP. (Separately, one inadvertent identify
  call fired during e2e testing before the test's key isolation
  was fixed — it returned an error body, BAD_MODEL_RESPONSE,
  worst-case cost about a cent of credits.)
- **Ingest**: JPEG EXIF and PNG eXIf orientation are implemented
  (all 8 transforms), pixel-hash-matched to Pillow on fixtures.
  **HEIC is the one deliberate exception**: Python decodes it via
  pillow-heif; the Rust decoder is hand-rolled PNG/JPEG, and
  linking libheif would break the single static binary. HEIC
  inputs stay on the Python path.
- **`describe_color_profile` is simplified**: it does not parse
  the ICC description string; profiles are pinned by sha256
  everywhere it matters, and the human-readable label is coarser
  than Python's.
- **`extract_foreground` size mismatch panics** (assert) where
  Python raises ValueError; both hard-fail, different mechanism.
- **PNG encoder output bytes differ from Pillow's** (different
  filter choices). Pixel fidelity is the invariant and is proven;
  file hashes therefore match only for files the Rust side did not
  re-encode — receipts record both file and pixel hashes exactly
  like Python's.
- **The estimator is ported** (`src/measure.rs`, CLI subcommand
  `measure`), including the AH-35 close-up envelope gate the
  Python fix lane added. Its OpenCV internals are cloned at the
  algorithm level (findHomography incl. the deterministic RANSAC
  RNG stream and LM refinement; adaptiveThreshold's
  round-then-subtract comparison, which bit-matches the ink mask
  on the battery scenes; approxPolyDP transliterated). Two
  honest boundaries:
  - HoughLinesP is randomized in OpenCV, so segment extraction is
    a deterministic approximation (same accumulator geometry and
    thresholds; endpoints on the accumulator line, as OpenCV
    reports them). Quad selection scores all ring-passing quads
    and takes the best loose score — the selection rule in
    Python's own docstring — instead of Python's first-12, whose
    membership is an artifact of the randomized extraction order.
  - Validation is on rendered scenes, exactly like Python's:
    no photo-real validation yet (waits on printed cards and
    real photos, same gate as the Python estimator).
  Minor: `verify_files`' size-mismatch message prints `WxH`
  where Python prints its `(W, H)` tuple; text only.
- **Not ported**: any HTTP transport (Python is stdio-first too),
  OAuth/per-user keys (roadmap in both).
- The server has not been registered with a real MCP client
  (only the JSON-RPC e2e driver).
